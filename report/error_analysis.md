# 6. Error analysis (ร่าง)

> ร่างสำหรับหัวข้อ 6 ของรายงาน ตัวเลขทั้งหมดมาจาก `results/error_analysis_sheet.csv` และ `results/error_analysis_summary.csv`
> สร้างซ้ำได้ด้วย `python code/error_analysis.py --summarize` ใช้เฉพาะ valid และ sample_labeled ไม่ได้ใช้ข้อความใน test

## 6.1 วิธีการ

วิเคราะห์ข้อที่โมเดลหลัก **E2** (ค่าเฉลี่ยความน่าจะเป็นของ WangchanBERTa C1, C2 และ TF-IDF LR A4) ทายผิด จากสองแหล่ง

- **sample_labeled:** ทายผิด 8 ข้อจาก 100 ข้อ (accuracy 92%) วิเคราะห์ทุกข้อ ชุดนี้ติด label ตามนิยามในโจทย์ ข้อผิดทุกข้อจึงเป็นความผิดของโมเดล
- **valid:** ทายผิด 665 ข้อจาก 2,669 ข้อ (accuracy 75.1%) สุ่มมา 50 ข้อ (seed 42)

แต่ละข้อตรวจสองขั้น
1. label ใน valid ถูกต้องตามนิยามคลาสในโจทย์หรือไม่ ถ้าไม่ถูกต้อง จัดเป็น **label noise**
2. ถ้า label ถูกต้อง จัดกลุ่มสาเหตุที่โมเดลทายผิด

## 6.2 ภาพรวม: confusion matrix ของ E2 บน valid

| จริง \ ทาย | pos | neu | neg | q |
|---|---|---|---|---|
| **pos** | 296 | 134 | 40 | 6 |
| **neu** | 187 | 1078 | 133 | 58 |
| **neg** | 14 | 73 | 589 | 6 |
| **q** | 0 | 9 | 5 | 41 |

ความสับสนส่วนใหญ่อยู่ที่เส้นแบ่งระหว่าง `neu` กับคลาสอื่น คู่ที่พบบ่อยที่สุดคือ neu→pos (187), pos→neu (134), neu→neg (133) และ neu→q (58) ส่วน pos กับ neg แทบไม่สับสนกันเลย (pos→neg 40, neg→pos 14) แสดงว่าโมเดลแยกขั้วบวกและลบได้ดี ปัญหาอยู่ที่การตัดสินว่าข้อความมีอารมณ์หรือไม่

## 6.3 ข้อค้นพบหลัก: ข้อผิดใน valid มากกว่าครึ่งมาจาก label ที่ผิด

จากข้อผิด 50 ข้อที่สุ่มจาก valid มี **26 ข้อ (52%)** ที่ label ใน valid ไม่ตรงกับนิยามในโจทย์ ช่วงความเชื่อมั่น 95% อยู่ที่ประมาณ 38–66% เพราะสุ่มมาแค่ 50 ข้อ ใน 26 ข้อนี้ **E2 ทายตรงกับ label ที่ถูกต้อง 23 ข้อ**

| รูปแบบของ label noise | จำนวน | ตัวอย่าง |
|---|---|---|
| คำถามขอข้อมูลสินค้า แต่ติดเป็น neu หรือ neg (ควรเป็น q) | 9 | "ขอรายละเอียด honda civic หน่อยครับ", "อยากได้ค่ะ หาซื้อได้ที่ไหนคะ", "กี่โมงถึงกี่โมง" |
| ชม รัก อยากได้ชัดเจน แต่ติดเป็น neu (ควรเป็น pos) | 7 | "รักจังรถHonda city ...", "อยากได้อ่ะ แต่ต้องไปกินที่พะเยา", "Goๆๆ" |
| ไม่มีอารมณ์ แต่ติดเป็น pos (ควรเป็น neu) | 4 | "เดี๋ยวส่งมาให้เอง 55", "#ชาบู #ช้างคลาสสิค" |
| ตำหนิหรือบ่นชัดเจน แต่ติดเป็น neu (ควรเป็น neg) | 3 | "...ตรรกะไรเนี่ย พังมาก...", "...เอาไปคิดภาษีเงินได้อีก เจ๊งสิครับ" |
| อื่นๆ | 3 | "โตโยต้า รีโว้นี้หรูแล้วหราา" ติดเป็น q แต่เป็นคำถามประชด ไม่ได้ขอข้อมูล |

รูปแบบที่พบบ่อยที่สุดคือคำถามขอข้อมูลที่ถูกติดเป็น `neu` ตรงกับที่โจทย์เตือนไว้

**ผลต่อการตีความคะแนน:**
- **valid ประเมินโมเดลต่ำกว่าความจริง** ถ้า 52% ของข้อผิดเป็น label noise และ E2 ทายถูกตามนิยามใน 23/26 ของกรณีนั้น ข้อผิดประมาณ 300 ข้อจาก 665 ข้อน่าจะไม่ใช่ข้อผิดจริง accuracy ที่ปรับแล้วจะประมาณ 86% ซึ่งใกล้กับ 92% บน sample_labeled ตัวเลขนี้เป็นการประมาณจาก 50 ข้อเท่านั้น
- เรื่องนี้อธิบายได้ว่าทำไม macro-F1 บน valid (0.675) ต่ำกว่าบน sample (0.933) มาก และเป็นเหตุผลที่เราคาดว่าคะแนน test ซึ่งติด label สม่ำเสมอแบบเดียวกับ sample จะสูงกว่า valid
- เรื่องนี้ยังอธิบายผลของแนวทาง B ได้ด้วย ทั้งการเพิ่ม feature คำถาม (B2) และการแก้ label ใน train (B4) ทำให้โมเดลทาย `q` ตามนิยามมากขึ้น แต่ valid ติด label ผิดแบบเดียวกับ train จึงนับการทายที่ถูกตามนิยามว่าผิด **valid จึงวัดประโยชน์ของการแก้ label noise ไม่ได้**

## 6.4 ความผิดพลาดจริงของโมเดล (label ถูกต้อง)

ข้อผิดที่ label ถูกต้องมี 32 ข้อ (sample 8 ข้อ และ valid 24 ข้อ) แบ่งตามสาเหตุดังนี้

| สาเหตุ | จำนวน | ตัวอย่าง (label จริง → E2 ทาย) | คำอธิบาย |
|---|---|---|---|
| **ติดคำสำคัญ** (keyword trap) | 12 | "บางคนชอบแบบมีน้ำตาล บางคนชอบแบบไม่หวาน แล้วแต่คน" (neu → pos)<br>"พัทยาเดินทางสะดวก มีรถตู้หลายเที่ยว" (neu → pos)<br>"พนักงานแจ้งว่าต้องรอประมาณยี่สิบนาที" (neu → neg)<br>"โปรโมชั่นเด็ดมากๆ ... ราคาถูกสุดๆ" (neu → pos)<br>"โอ้ยหิว" (neu → pos) | ประโยคเป็นข้อเท็จจริงหรือโฆษณา แต่มีคำที่มักมากับอารมณ์ (ชอบ, สะดวก, ต้องรอ, เด็ด, หิว) โมเดลให้น้ำหนักกับคำมากกว่าเจตนาของประโยค |
| **สองด้านหรือการเปรียบเทียบ** | 6 | "ราคาสูงกว่าร้านอื่นนิดหน่อย แต่ปริมาณก็เยอะกว่า" (neu → neg)<br>"ตัวจริงสวยกว่าในจอ" (pos → neg) | ต้องชั่งน้ำหนักสองส่วนของประโยค หรือเข้าใจว่าการเปรียบเทียบเป็นคำชม ทั้งสามโมเดลทาย "สวยกว่าในจอ" ผิดเหมือนกัน |
| **อารมณ์ที่ไม่มีคำบอกตรงๆ** | 5 | "เหงามาก ไม่มีใครคุยด้วยเลย" (neg → neu)<br>"คิดถึงแม่รุ้งอีกแล้ว" (pos → neu) | ความรู้สึกที่ไม่มีคำบ่นหรือคำชมตรงๆ |
| **สแลงหรือสำนวน** | 4 | "ปลาทูแม่กลองหน้างอคองอ" (neu → neg)<br>"งื้ออออ อยากจินนจุงง" (neu → pos) | "หน้างอ" ปกติใช้กับคน แต่ประโยคนี้หมายถึงลักษณะของปลา คำที่สะกดเลียนเสียงทำให้ตีความยาก |
| **ประชด** | 3 | "เยี่ยมเลย ฝนตกวันที่ลืมพกร่มพอดี" (neg → pos)<br>"ยึดแค่กระเป๋าพอแล้วมั้ง ... เหมือนมีอะไรแอบแฟง 555" (neg → neu) | ใช้คำบวกพูดถึงเรื่องแย่ ต้องรู้ว่าสถานการณ์นั้นแย่ |
| **กำกวม** | 2 | "ทำไมไม่ทำของนาวาร่าตัวเก่าเป็นแบบนี้บ้างเนาะ" (neu → neg) | คนอ่านเองก็ตัดสินได้ไม่ชัด |

**ข้อสังเกต:** ทุกกลุ่มเป็นกรณีที่ต้องเข้าใจ **เจตนาของทั้งประโยค** ไม่ใช่ดูแค่คำ กลุ่มที่ใหญ่ที่สุดคือ keyword trap ซึ่งเป็นจุดอ่อนของ bag-of-words โดยตรง และ WangchanBERTa ก็ยังพลาดในกรณีส่วนใหญ่ของกลุ่มนี้

## 6.5 ทำไม ensemble ถึงช่วย

ในข้อผิดจริง 32 ข้อของ E2 พบว่า **A4 ทายถูก 7 ข้อ และ C1 ทายถูก 8 ข้อ** ซ้ำกันแค่ 2 ข้อ แต่ละโมเดลจึงพลาดคนละแบบ

- **A4 ถูก แต่ BERT ผิด:** "เหงามาก ไม่มีใครคุยด้วยเลย" (neg) และ "ยึดแค่กระเป๋าพอแล้วมั้ง ..." (neg) TF-IDF จับคำอย่าง "เหงา" ที่ train มักติดเป็น neg ได้ตรงๆ
- **BERT ถูก แต่ A4 ผิด:** "งื้ออออ อยากจินนจุงง" และ "เราจะพาเธอไปอ้วน" (neu ทั้งคู่) A4 ถูกคำว่า "อยาก" ดึงไปเป็น pos ส่วน BERT ดูบริบททั้งประโยค

เมื่อสองโมเดลผิดคนละแบบ การเฉลี่ยความน่าจะเป็นจะแก้ข้อผิดของกันและกันได้ส่วนหนึ่ง สอดคล้องกับผลในตาราง ensemble: valid macro-F1 ขึ้นจาก 0.668 (C1) เป็น 0.675 และ sample ขึ้นจาก 0.794 เป็น 0.933

## 6.6 สรุปและแนวทางปรับปรุง

1. **label noise เป็นปัญหาใหญ่ที่สุดของการวัดผล ไม่ใช่ของโมเดล** การเลือกโมเดลด้วย valid อย่างเดียวจึงลำเอียงไปทางโมเดลที่เลียนแบบ noise ใน train เราจึงดู sample_labeled ประกอบเสมอ
2. ความผิดพลาดจริงที่เหลือเป็นเรื่องความหมายระดับประโยค (keyword trap, สองด้าน, ประชด) ซึ่งเป็นจุดที่ pretrained model ทำได้ดีกว่า bag-of-words แต่ยังไม่หมด
3. ถ้ามีเวลาเพิ่ม ทางที่น่าจะช่วยได้คือ
   - ติด label ส่วนเล็กๆ ของ valid ใหม่ตามนิยามในโจทย์ เพื่อให้มีชุดวัดผลที่เชื่อถือได้และใหญ่กว่า sample
   - เพิ่มตัวอย่างข้อความเชิงข้อเท็จจริงหรือโฆษณาที่มีคำอารมณ์ เพื่อแก้ keyword trap
   - train BERT ให้นานขึ้น เพราะ valid ยังขึ้นต่อเนื่องจนถึง epoch สุดท้าย (0.624 → 0.651 → 0.668)
